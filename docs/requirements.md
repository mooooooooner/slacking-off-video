# 需求目标 — FramelessViewer

> 本文档记录项目的目标、范围与验收标准，作为后续开发与验收的基准。
> 版本变更记录见 [`CHANGELOG.md`](./CHANGELOG.md)。

---

## 1. 项目定位

一个 **无边框透明浏览器**：屏幕上只显示网页内容本身，没有标题栏、地址栏、菜单栏、标签栏。

与浏览器插件的关键区别：浏览器扩展**无法**设置操作系统窗口的透明度、无法去掉系统标题栏，
因此本项目采用 **Electron 桌面应用** 形态，而非浏览器插件。

---

## 2. 目标（Goals）

| 编号 | 目标 |
| --- | --- |
| G-1 | 网页内容独占窗口，界面上不出现任何常驻的浏览器控件（地址栏 / 标签栏 / 菜单 / 标题栏） |
| G-2 | 窗口大小与宽高比可自由调整 |
| G-3 | 整个窗口的透明度可自由调节 |
| G-4 | 用快捷键一键进入 / 退出「悬浮浏览模式」 |
| G-5 | 需要操作时，控制界面才出现；不需要时完全不可见 |

## 3. 非目标（Non-Goals）

| 编号 | 非目标 | 原因 |
| --- | --- | --- |
| NG-1 | 多标签页 / 书签 / 历史 / 扩展支持 | 目标是「极简查看器」，不是完整浏览器 |
| NG-2 | 逐像素透明（页面背景透视到桌面） | Electron 的 `transparent: true` 官方限制「窗口不可缩放」，与 G-2 直接冲突 |
| NG-3 | 修改 / 破解站点自身样式与脚本 | 只做滚动条这类外观层面的最小干预 |
| NG-4 | 跨平台发行 | 当前只交付 Windows x64 |

---

## 4. 功能需求

### FR-1 无边框与窗口布局

| 项 | 内容 |
| --- | --- |
| 需求 | 窗口 `frame: false`，不渲染任何常驻浏览器控件 |
| 验收 | 启动后截图中除网页内容外，只有隐含的 10px 顶部拖拽热区；控制层默认 `display: none` |

### FR-2 调整窗口大小与比例

| 项 | 内容 |
| --- | --- |
| 需求 | 鼠标拖动窗口边缘 / 四角即可缩放；可锁定宽高比 |
| 验收 | 四边与四角均可拖动缩放；`Ctrl+Alt+R` 在 自由 / 16:9 / 4:3 / 1:1 / 21:9 / 3:2 / 9:16 之间循环；锁定后拖动仍保持比例 |
| 备注 | **不提供**调整大小的快捷键（用户明确不需要），仅保留鼠标操作与控制面板按钮 |

### FR-3 透明度调节

| 项 | 内容 |
| --- | --- |
| 需求 | 窗口整体不透明度可调，范围 10% ~ 100% |
| 验收 | 控制面板滑块、`Ctrl+Alt+↑/↓`（每次 10%）、托盘预设均生效；数值重启后保持 |
| 实现 | `win.setOpacity()`（整窗均匀透明），**不使用** `transparent: true`，以保住 FR-2 的缩放能力 |

### FR-4 统一窗口模式

| 项 | 内容 |
| --- | --- |
| 需求 | 把「置顶 / 鼠标穿透 / 悬浮」合并成**单个**快捷键，窗口无焦点时也生效 |
| 模式 | **普通**（不置顶、不穿透）→ **悬浮**（置顶 + 预设不透明度 85%）→ **穿透**（置顶 + 预设不透明度 + 鼠标穿透）→ 普通 |
| 验收 | `Ctrl+Alt+F` 全局生效，按一次前进一档、循环；进入悬浮 / 穿透时使用预设不透明度，退回普通时**完整还原**进入前的不透明度；窗口失焦（点击其他窗口 / Alt+Tab）后仍保持置顶 |
| 控制面 | 控制面板「窗口模式」三个按钮、托盘子菜单均可直接选择某一模式 |

### FR-5 隐藏式操作入口

| 项 | 内容 |
| --- | --- |
| 需求 | 没有地址栏的前提下仍能导航；控制界面不常驻 |
| 验收 | `Ctrl+L` 唤出半透明网址输入条（回车加载、`Esc` 取消）；`Ctrl+Alt+P` 或右上角 `⚙` 打开控制面板；`Esc` 隐藏全部浮层 |

### FR-6 鼠标穿透

| 项 | 内容 |
| --- | --- |
| 需求 | 可将鼠标点击穿透到下层窗口 |
| 验收 | 作为「窗口模式 → 穿透」的一档（`Ctrl+Alt+F`），或将 `Ctrl+Alt+F` 切到普通 / 悬浮、或按 `Esc` 退回悬浮来关闭；开启后窗口不接收鼠标事件；关闭后窗口回到最前 |
| 备注 | 穿透状态**不跨重启保留**，避免开机后点不到窗口；退出时若处于穿透，下次启动降级为悬浮。非普通模式时窗口左上角常驻**模式徽标**，穿透时明确提示「点击已穿透」及切回快捷键，避免误以为卡死 |

### FR-7 网页内全屏限制在窗口内

| 项 | 内容 |
| --- | --- |
| 需求 | 网页（如视频播放器）调用 `requestFullscreen()` 时，只让画面铺满本窗口，**不得把窗口顶成系统全屏** |
| 验收 | 全屏前后窗口内容尺寸不变；全屏期间自动收起浮层并让出顶部 10px 拖拽条；退出后状态全部恢复 |
| 实现 | `fullscreenable: true` + `disableHtmlFullscreenWindowResize: true`，并以 `enter-html-full-screen` 兜底还原 |

### FR-8 去掉网页滚动条

| 项 | 内容 |
| --- | --- |
| 需求 | 隐藏网页右侧 / 底部的滚动条 |
| 验收 | 滚动条不可见，但滚轮 / 触摸板 / 键盘滚动功能完全正常；`Ctrl+Alt+S` 或托盘可切回显示 |

### FR-9 一键关闭

| 项 | 内容 |
| --- | --- |
| 需求 | 提供一键退出程序的快捷键 |
| 验收 | `Ctrl+Alt+Q` 全局生效并立即退出（同时释放全局快捷键与托盘） |

### FR-10 设置持久化

| 项 | 内容 |
| --- | --- |
| 需求 | 网址、不透明度、宽高比、窗口位置尺寸、窗口模式、滚动条偏好、开屏动画开关重启后保持 |
| 存储 | `%APPDATA%\framelessviewer\settings.json` |
| 例外 | 鼠标穿透状态不持久化（退出时若为「穿透」，重启降级为「悬浮」） |

### FR-11 网页缩放

| 项 | 内容 |
| --- | --- |
| 需求 | 可缩放网页内容，便于看清细节 / 缩小取景 |
| 验收 | `Ctrl + =` / `Ctrl + +`（含小键盘 `+`）放大、`Ctrl + -` 缩小、`Ctrl + 0` 复位；只影响网页，不影响外壳控件 |

### FR-12 开屏动画

| 项 | 内容 |
| --- | --- |
| 需求 | **每次启动**都先播放一段开屏动画，再进入上次记忆的网页；动画可关闭 |
| 验收 | 默认播放（图标描边 + 标题渐显 + 柔光呼吸，纯 CSS）；动画结束后**自动进入记忆的网址**（没有网址则停在开屏页等待 `Ctrl+L`）；控制面板「开屏动画」或托盘可关闭，关闭后跳过开屏、直接进入网页 |
| 备注 | 系统开启「减少动态效果」时以静态画面快速跳过，不长时间停在静态开屏页 |

### FR-13 网页内链接跳转

| 项 | 内容 |
| --- | --- |
| 需求 | 点击网页里的各种链接都能正常跳转，包括 `target="_blank"` / `window.open` 打开的「新窗口」链接 |
| 验收 | 普通链接、`target="_blank"`、`window.open` 均在**同一个 webview 内**打开（不新建系统窗口）；非 `http(s)/file/about` 协议（如 `mailto:`、`tg:`）交给系统处理 |
| 实现 | `<webview allowpopups>` + 主进程 `setWindowOpenHandler` 返回 `deny`，并在 `setImmediate` 中 `loadURL`。**缺少 `allowpopups` 时 Chromium 会在请求到达 handler 之前就拦掉弹窗**，表现为这类链接点了没反应 |
| 备注 | 单视图设计：链接始终在原窗口内打开，不产生多标签 / 多窗口 |

## 5. 非功能需求

| 编号 | 需求 |
| --- | --- |
| NFR-1 | **安全**：窗口渲染进程 `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`；网页在 `<webview>` 中运行且被强制剥离 preload |
| NFR-2 | **最小 API 面**：渲染进程只能访问 `window.frameless` 暴露的白名单方法，拿不到 `fs` / 任意 IPC |
| NFR-3 | **不干扰系统**：只把「必须全局可用」的快捷键注册为系统级，避免抢占其他软件的组合键 |
| NFR-4 | **零打包器**：主进程与渲染层均为原生 JS（CommonJS），`npm start` 直接可跑 |
| NFR-5 | **可交付**：能用 electron-builder 产出 Windows 免安装 exe |

## 6. 关键技术决策

| 决策 | 选择 | 原因 |
| --- | --- | --- |
| 形态 | Electron 桌面应用 | 浏览器扩展无 API 可改窗口透明度 / 去掉系统标题栏 |
| 透明度 | `win.setOpacity()` | `transparent: true` 官方限制「不可缩放」，与 FR-2 冲突 |
| 页面承载 | `<webview>` | 控制层与不可信网页进程隔离，且浮层可正常叠在网页之上 |
| 网页弹窗 | `<webview allowpopups>` + `setWindowOpenHandler` 返回 `deny` + `setImmediate(loadURL)` | 单视图内跳转；缺少 `allowpopups` 时弹窗会在到达 handler 前被 Chromium 拦掉，`target="_blank"` 链接点了没反应 |
| 全屏 | `fullscreenable: true` + `disableHtmlFullscreenWindowResize: true` | 设 `fullscreenable: false` 会让 `requestFullscreen()` 直接失败，反而不满足 FR-7 |
| 滚动条 | `webContents.insertCSS()` | 不改站点代码，只覆盖外观；导航后重新注入 |
| 全局快捷键 | 仅 F / H / Q | 置顶 / 穿透 / 悬浮合并为 `F` 的模式循环；曾把 `Ctrl+Alt+方向键` 注册为全局，会直接破坏其他软件的组合键 |
| 应用菜单 | `Menu.setApplicationMenu(null)` | 符合无边框定位；并避免默认菜单的缩放加速键与自实现的 `Ctrl + =` / `Ctrl + 0` 重复触发 |
| 开屏动画 | 纯 CSS，关闭时 `insertCSS` 注入静态样式 | 起始页无需脚本（CSP 默认禁止），只有起始页会注入，不影响真实网页 |

## 7. 已知限制

1. 关闭窗口 = 收进托盘，不退出程序；退出走 `Ctrl+Alt+Q` 或托盘菜单。
2. 隐藏滚动条对个别依赖滚动条宽度的站点可能造成轻微布局变化（可用 `Ctrl+Alt+S` 关闭）。
3. Windows 上任务栏缩略图不会随窗口透明度变化，属系统行为。
4. 首次 `npm install` 若下载 Electron 二进制缓慢，需配置镜像（见 README）。
5. 全局快捷键若被其他软件占用，启动时会在终端告警，此时窗口内的同名组合仍可用。

## 8. 验收方式

- **静态**：`node --check` 全部源码通过语法检查。
- **运行时**：`npm run dev` 启动，渲染进程 console 无报错。
- **行为**：通过 Electron 远程调试端口（`--remote-debugging-port`）接入 CDP，
  在真实网页上断言窗口尺寸、`scrollbar-width`、`clientWidth === innerWidth`、
  全屏前后尺寸一致性等指标。v0.2.0 的 11 项断言全部通过。
